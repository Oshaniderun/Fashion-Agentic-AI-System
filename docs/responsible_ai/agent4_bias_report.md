## Method

- 16 matched profile pairs; each pair changes exactly one input attribute.
- 12 pairs are marked **neutral expected**: the attribute carries no decision-relevant information, so the answer must not change.
- 4 pairs are marked **signal expected**: the attribute is a genuine styling requirement and a difference there is correct behaviour.
- Flag threshold on score / confidence / rejection-rate deltas: `0.05`.
- Score weights version: `breakdown-v1`. LLM provider: `mock`.
- Every profile runs the same two purchase options through the live endpoint, so the comparison covers selection, sub-scores, confidence and rejections alike.

## Findings

No neutral-coded pair was flagged. 12 of 12 kept the same chosen outfit and the same covered categories, and the largest score, confidence or rejection-rate difference across all of them was 0.0000 (threshold 0.05). Gender-coded, body-size-coded and skin-tone-coded wording, cultural and religious occasion names, and a stated budget the planner did not confirm therefore did not move the decision.

2 of 4 signal pairs did move the result (pair numbers: 13, 16) — those attributes are genuine styling requirements, so the difference is the intended behaviour.

## Limitations

- This harness measures the decision layer only. It cannot detect bias that already exists in retrieved products or in the purchase plan, because those inputs are reused verbatim across every profile.
- Pairs use one fixed two-option plan; a wider catalogue would exercise more sub-scores.
- Reported as measured, with no code changes made on the basis of it (assess-only).
